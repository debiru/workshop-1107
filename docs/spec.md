# PhoenixField 仕様書

## 目的

Web ページのフォームに多くの項目や長文を入力したにもかかわらず、ブラウザのクラッシュや Web サイト側のセッションタイムアウトなどで入力内容が失われる事故を防ぐ。

## 対象

- Google Chrome 拡張機能（Manifest V3）
- 対象要素：`<textarea>` と、テキスト系の `<input>`（`type` が text / email / search / url / tel、または type 属性なし）
  - `type="password"` は常に対象外。その他の type（checkbox、range、file 等）も対象外
  - 設定で「text と textarea のみ」に絞ることもできる

## 自動保存

- 対象要素への `input` イベントを検出し、0.8 秒のデバウンス後に内容を保存する
- 保存先は `chrome.storage.local` のみ。外部送信は行わない
- データはページごとに管理する
  - ページID：URL からハッシュフラグメント（`#` 以降）を除いたもの。クエリパラメータはキー順に整列してから含める（並び順違いで別ページ扱いにならないようにするため）
  - ページIDには origin とパス名も併せて保持し、呼び出し範囲の切り替えに使う

## 保存データとフォームコントロールの関係

- 保存データとフォームコントロールは自動的には関連付けない
  - 保存時にどの要素から保存したか（タグ、type、name、id、ラベル等）は「目安情報」として保持するが、それを使って復元先を自動決定することはしない
  - 理由：ページ側の HTML 設計が変わっても（例：`name="contact-body"` → `name="inquiry-body"`）、保存データを新しいフォームに復元できるようにするため
- 復元は、ユーザーがページ内ツールバーで保存データとフォームコントロールを手動で対応付け、「自動入力を実行」ボタンで実行する

## 世代管理

- 各保存データは「最新版」を常に保持する
- 世代スナップショットの追加条件（いずれか）
  - 前回の世代から設定間隔（初期値3分）以上経過し、かつ内容が設定量（初期値10文字）以上変化した
  - 内容が直前の最新版の半分以下に急減した場合は、直前の内容を緊急スナップショットとして残す（誤操作による全削除対策）
- 世代の上限は保存データあたり初期値30件、設定で最大100件まで変更可能。超えた分は古い世代から削除する
- 世代は保持日数（初期値90日）を過ぎたら自動削除する
- ストレージ使用量が上限（約10MB）の約8割を超えた場合、最新版は残し、古い世代から全体ローテートで削除する
- `unlimitedStorage` permission は要求しない（permissions 最小限の原則）

## ページ内ツールバー

- ページ下部に固定表示し、details 要素のように開閉できる操作エリア（Shadow DOM で実装し、ページの CSS と干渉しない）
- ポップアップやモーダルは使用しない。フォームのフォーカスごとの自動表示も行わない
- 機能
  - 表示範囲の切り替え：このページ／同じパスでクエリ違い／同じドメイン内／すべて
  - 保存データの一覧（目安情報、更新日時、文字数、世代の選択、プレビュー、個別削除）
  - ページ内フォームコントロールの一覧
  - 保存データ（世代を含む）とコントロールの対応付けの追加・取り消し
  - 「自動入力を実行」で、対応付けしたすべての入力先に値をセットし、`input` / `change` イベントを発火させる
- アクセシビリティ：実ボタンとセレクトで操作でき、キーボード操作可能。状態通知には `aria-live` を使用し、文字色は十分なコントラストを確保する

## 設定画面

- 自動保存の ON / OFF、対象範囲、世代の最大保持数、スナップショット間隔と変化量、世代の保持日数
- 保存データの一覧（ページ単位の削除、全削除）、JSON エクスポート、ストレージ使用量の表示

## permissions

- `storage` のみ。理由は README.md に記載
- 全 http / https ページへの content script は、フォーム検出とツールバー表示のために必要

## 制約

- 外部から取得したコードは実行しない（Manifest V3 のルール）。この拡張機能のコードはすべて同梱ファイルのみで構成する
